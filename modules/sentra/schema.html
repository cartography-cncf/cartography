SentraAlert#

An active Sentra alert: a policy violation on a data store or identity.

The Sentra UI calls these issues. Cartography imports alerts whose status is pending, opened, or in_progress; cleanup removes alerts that Sentra resolved or ignored since the last sync.

For an alert on a data store, Cartography also reads the objects that violate the policy, such as files in a bucket. The alert links with INVOLVES to the data classes found in those objects, and with AFFECTS to the stores that hold them. Cartography doesn’t create nodes for the objects themselves.

When an affected data store represents an AWS resource, the alert also links with AFFECTS directly to that resource, as findings from other security tools do. Queries that match (:SecurityIssue)-[:AFFECTS]->(:ObjectStorage) then include alerts on S3 buckets, and queries that match (:SecurityIssue)-[:AFFECTS]->(:Database) include alerts on RDS instances, DynamoDB tables, and Redshift clusters. An RDS cluster has no Database label, because its member instances carry it.

Ontology Mapping: This node uses the ontology label SecurityIssue.

Relationships#

  • (:SentraAlert)-[:AFFECTS]->(:AWSDynamoDBTable): The DynamoDB table that a data store affected by the alert represents, matched on the table ARN.

  • (:SentraAlert)-[:INVOLVES]->(:SentraDataClass): A data class that Sentra found in an object that violates the policy.

  • (:SentraTenant)-[:RESOURCE]->(:SentraAlert): The Sentra organization that raised the alert.

SentraDataStore#

A data store that Sentra discovered and classified, such as an S3 bucket, a database, or a SaaS drive.

The node is Sentra’s view of the store: its sensitivity, the data classes found in it, and its security posture. Where Sentra’s identifier proves which AWS resource the store is, the node links to that resource with MONITORS. Data stores in other clouds and in SaaS applications have no MONITORS link.

SentraPolicy#

A Sentra policy: a rule that raises an alert when a data store or identity violates it.

The node holds the context of a violation: the compliance frameworks that the policy maps to, the risk that it detects, and how to remediate it. Cartography imports both enabled and disabled policies. Each alert links to the policy that raised it with GOVERNED_BY, and the policy links with CLASSIFICATION to the data classes that its rules check for.
