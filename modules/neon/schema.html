NeonApiKey#

Represents an organization API key. A key with a project_id is limited to that project; one without it can manage every project in the organization.

Ontology Mapping: This node uses the ontology label APIKey.

Properties#

Ontology-generated fields are shown in italics.

Field

Index

Description

id

Yes

The numeric API key id, as a string. The token itself is never returned by the API

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

created_at

When the API key was created

created_by_id

User id of the member who created the key

created_by_name

Display name of the member who created the key

last_used_at

When the key last authenticated a request

last_used_from_addr

The IP address the key was last used from

name

Yes

Name of the API key

org_id

Id of the organization the key belongs to

project_id

When set, the key is scoped to this single project instead of the whole organization

_ont_created_at

Yes

Normalized field sourced from created_at.

_ont_last_used_at

Yes

Normalized field sourced from last_used_at.

_ont_name

Yes

Normalized field sourced from name.

NeonBranch#

Represents a Neon branch: a copy-on-write clone of the project’s data, together with its object storage buckets, roles and databases. A child branch carries a copy of its parent’s data, so a branch created from production holds production data.

Properties#

Field

Index

Description

id

Yes

The branch id (br-...), unique across Neon

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

created_at

When the branch was created

creation_source

How the branch was created (console, neonctl, …)

current_state

Lifecycle state of the branch (init, ready, …)

default

Whether this is the project’s default branch

expires_at

When the branch is deleted automatically, if it has an expiry

init_source

What the branch was seeded with: parent-data copies the parent’s data, schema-only copies only its schema

logical_size

Logical size of the branch’s data, in bytes

name

Yes

Name of the branch

parent_id

Id of the branch this one was created from. Absent on the root branch

parent_timestamp

Point in the parent’s history the branch was created from

primary

Deprecated alias of default still returned by the API

project_id

Id of the project the branch belongs to

protected

Whether the branch is protected. When the project’s IP allowlist sets protected_branches_only, protected branches are the only ones it restricts

updated_at

When the branch was last changed

NeonEndpoint#

Represents a Neon compute endpoint: the Postgres server that serves one branch and the hostname clients connect to.

exposed_internet is True when any internet address may connect to the compute. The project’s IP allowlist, block_public_connections, and the compute’s disabled flag all feed the verdict. An allowlist with protected_branches_only applies to protected branches only, so a preview branch’s compute stays exposed even when the project looks locked down.

Properties#

Field

Index

Description

id

Yes

The compute endpoint id (ep-...), unique across Neon

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

autoscaling_limit_max_cu

Maximum compute size, in compute units

autoscaling_limit_min_cu

Minimum compute size, in compute units

branch_id

Id of the branch this compute serves

compute_release_version

The compute image release

created_at

When the compute was created

creation_source

How the compute was created (console, neonctl, …)

current_state

Lifecycle state (init, active, idle)

disabled

Whether connections to the compute are refused

exposed_internet

Yes

True when any internet address may open a connection: public connections are not blocked, the compute is not disabled, and no IP allowlist applies to its branch (or the allowlist contains 0.0.0.0/0 or ::/0)

exposed_internet_type

Yes

How it is exposed. Always direct, since the hostname resolves to the compute’s own proxy

host

Yes

The hostname Postgres clients connect to

last_active

When the compute was last active

name

Optional display name of the compute endpoint

passwordless_access

Whether the compute accepts passwordless (Console-brokered) authentication

pooled_host

Yes

The hostname of the connection pooler in front of this compute

pooler_enabled

Whether the deprecated per-endpoint pooler flag is set. The pooled hostname works either way

pooler_mode

The connection pooler mode

region_id

The region hosting the compute

suspend_timeout_seconds

Seconds of inactivity before the compute scales to zero. 0 uses the default, -1 never suspends

type

read_write for the branch’s primary compute, read_only for a read replica

updated_at

When the compute was last changed

NeonStorageBucket#

Represents a Neon Object Storage bucket as served by one branch.

Buckets branch with the database: a child branch serves its own copy of its parent’s buckets from its own S3 endpoint, so Cartography records one node per branch. exposed_internet is True for public_read buckets, which the object_storage_public rule reports.

Ontology Mapping: This node uses the ontology label ObjectStorage.

Properties#

Ontology-generated fields are shown in italics.

Field

Index

Description

id

Yes

Synthesised as <branch id>/<bucket name>

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

access_level

public_read lets anyone read objects without credentials, private requires a credential

branch_id

Id of the branch serving this copy of the bucket

created_at

When the bucket was created

exposed_internet

Yes

True when the bucket is public_read, meaning every object is readable without authentication

exposed_internet_type

Yes

How it is exposed. Always direct, since objects are served from the branch’s own S3 endpoint

name

Yes

Name of the bucket

public

True when access_level is public_read

region

The S3 signing region of the branch’s storage

s3_endpoint

The branch’s S3-compatible endpoint URL. Objects are addressed path-style as <s3_endpoint>/<bucket>/<key>

url

Yes

The bucket’s base URL, <s3_endpoint>/<bucket>. For a public_read bucket every object under it is readable without credentials

_ont_location

Yes

Normalized field sourced from region.

_ont_name

Yes

Normalized field sourced from name.

_ont_public

Yes

Normalized field sourced from public.

_ont_source

Module that populated this node’s ontology fields.
