LangSmithAccessPolicy#

An attribute-based access control policy. Policies attach to roles and restrict which tagged resources the role’s permissions apply to.

Properties#

Field

Index

Description

id

Yes

Access policy UUID.

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

condition_summary

Flattened, human-readable rendering of the policy’s attribute-based condition groups, for example ‘project.tag in [prod]’.

description

Human-readable description of the policy.

effect

Whether the policy allows or denies the matched resources.

name

Yes

Access policy name.

Relationships#

  • (:LangSmithAccessPolicy)-[:ATTACHED_TO]->(:LangSmithRole): An access policy narrows the resources a role applies to.

  • (:LangSmithOrganization)-[:RESOURCE]->(:LangSmithAccessPolicy): Links an organization to one of its access policies.

LangSmithAgent#

An agent (assistant) that can hold OAuth credentials.

Cartography discovers agents by listing each deployment’s assistants on its own data plane, because a LangGraph Platform agent id is an assistant id and the control plane doesn’t expose it. Deployments that declare an agent block, and credential records that name an agent, top up the inventory.

Properties#

Field

Index

Description

id

Yes

Synthetic identifier of the form <organization_id>|<assistant_id>. LangSmith derives an assistant id from its graph, so two organizations running the same graph can produce the same assistant id; namespacing keeps their agents, deployments and credential paths from merging.

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

assistant_id

Yes

The raw LangSmith assistant ID, as used by the agent-auth API.

created_at

Timestamp when the assistant was created.

description

Human-readable description of the agent.

environment

Environment the agent is deployed to, for example production.

graph_id

Identifier of the LangGraph graph this agent runs.

name

Agent name, taken from the deployment that serves it when one exists.

updated_at

Timestamp when the assistant was last updated.

version

Assistant version number.

Relationships#

  • (:LangSmithAgent)-[:HAS_CREDENTIAL]->(:LangSmithAgentCredential): The agent that can use this credential.

  • (:LangSmithOrganization)-[:RESOURCE]->(:LangSmithAgent): Links an organization to an agent running within it.

  • (:LangSmithDeployment)-[:RUNS]->(:LangSmithAgent): Links an agent to the deployment serving it.

Set when Cartography discovers the agent by listing the deployment’s assistants, which is the usual case. LangSmith fills a deployment’s own agent block only for deployments created with an explicit agent binding.

One-to-many: LangGraph derives an assistant id from its graph, so the same agent can be served by several deployments.

LangSmithAgentCredential#

A third-party OAuth token a LangSmith agent holds on a human’s behalf, letting the agent call that provider’s API as them.

Cartography ingests only metadata. oauth_token_id is an opaque reference, and Cartography never requests or receives an access token, refresh token, or client secret.

Properties#

Field

Index

Description

id

Yes

Agent connection UUID.

firstseen

Timestamp when a sync job first created this node.

lastupdated

Yes

Timestamp of the last sync that observed this node.

created_at

Timestamp when the connection was authorized.

expires_at

Timestamp when the stored token expires, or null if it does not expire.

oauth_token_id

Identifier of the stored token record. This is an opaque reference only; no access or refresh token material is ingested.

provider_account_label

Label identifying which upstream account the token belongs to.

scopes

OAuth scopes the stored token was granted.

Relationships#

  • (:LangSmithAgentCredential)-[:FOR_PROVIDER]->(:LangSmithOAuthProvider): The third-party provider this credential authenticates against.

Matched on the provider’s UUID, resolved during transform, rather than on its provider_id slug. The slug is operator-chosen, so two organizations can both define one called github-prod, and relationship matching carries no implicit organization constraint.

  • (:LangSmithAgent)-[:HAS_CREDENTIAL]->(:LangSmithAgentCredential): The agent that can use this credential.

  • (:LangSmithAgentCredential)-[:ON_BEHALF_OF]->(:LangSmithUser): The human whose third-party account the agent can act as. This is the edge that answers which agents hold which user’s OAuth tokens.

  • (:LangSmithOrganization)-[:RESOURCE]->(:LangSmithAgentCredential): Links an organization to an agent credential held within it.

LangSmithApiKey#

A LangSmith credential: a personal access token, an organization service key, a workspace API key, or a SCIM token. Cartography stores only the non-secret short prefix.

Ontology Mapping: This node uses the ontology label APIKey.

Name of the workspace this key targets when no workspace header is sent.

Timestamp when the key expires, or null if the key never expires.

One of pat (personal access token, lsv2_pt), service_key (organization service key, lsv2_sk), workspace_key (workspace API key, lsv2_sk) or scim_token (lsv2_sc).

  • (:LangSmithOrganization)-[:RESOURCE]->(:LangSmithApiKey): Links an organization to an API key issued within it.

A user’s membership in a single organization, together with the role they hold there.

Modeled as a node so that organization-specific state stays organization-specific: a user can belong to several organizations, and each has its own view of whether that identity is disabled, what role it holds and how it was provisioned.

LangSmithUser#

A LangSmith user account, keyed on the stable ls_user_id.

A user can belong to several organizations, so this node deliberately carries only identity that is true of the person everywhere. Everything organization-specific, such as whether the identity is disabled, which organization role it holds, and how it was provisioned, lives on LangSmithOrgMembership, because storing it here would mean one organization’s sync overwriting another’s view of the same human.

For the same reason the node has no sub-resource relationship: it is not owned by any single organization, and cleanup never deletes it, so one organization’s sync cannot destroy an identity another organization still references. Its relationships are all owned by organization-scoped schemas (memberships, keys, credentials) or by the organization-scoped MEMBER_OF matchlink, and cleanup prunes them with their owner.
